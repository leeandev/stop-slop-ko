# 서술형 글 시나리오 테스트

서브에이전트에게 stop-slop-ko의 SKILL.md와 references 경로를 주고, 빈 임시 폴더에 준비 파일을 만든 뒤 발화를 넣는다. 통과 기준을 모두 만족해야 PASS.

## 1. 블로그 글 정제

준비: `blog.md`

```markdown
# Docker 볼륨 정리

오늘은 Docker 볼륨에 대해 알아보겠습니다. 정말 많은 분들이 헷갈려 하시는 부분입니다.

컨테이너를 지우면 컨테이너 안에 쓴 파일도 함께 사라집니다. 볼륨은 이 데이터를 컨테이너 밖에 저장합니다.

`docker volume create mydata`로 볼륨을 만들고, `-v mydata:/var/lib/mysql`로 연결합니다. 제 테스트에서는 MySQL 컨테이너를 3번 지웠다 다시 만들어도 테이블 12개가 그대로 남았습니다.

이 글이 도움이 되셨길 바랍니다. 그럼 오늘도 즐거운 개발 되세요!
```

발화: "blog.md AI 티 빼줘"

통과 기준:
- 종결이 `~습니다`체 그대로다(`~다`로 바꾸지 않는다)
- "오늘은 ~ 알아보겠습니다", "정말", "도움이 되셨길 바랍니다" 같은 블로그 상투구가 빠진다
- 사실 문장과 숫자(3번, 테이블 12개), 명령어가 그대로 남는다
- `slop_scan.py --prose`를 실행하고 결과(PASS/FAIL)를 보고한다

## 2. 리포트 정제

준비: `report.md`

```markdown
# 재택근무가 팀 협업에 미친 영향

재택근무는 단순한 근무 형태가 아닌 일하는 방식의 전환이다. 본 보고서에서는 우리 팀의 재택근무 1년을 돌아보고자 한다.

우리 팀은 2025년 3월부터 주 3일 재택근무를 시작했다. 팀원은 8명이고 그중 5명이 수도권 밖에 산다. 통근 시간은 평균 왕복 2시간에서 0으로 줄었다. 나는 이것이 가장 큰 변화라고 생각한다.

또한 회의 방식도 바뀌었다. 주 5회이던 대면 회의가 주 2회 화상 회의로 줄었고, 나머지는 문서로 공유했다. 회의록을 남기는 비율은 30%에서 90%로 올랐다. 기록이 남으면서 결정이 뒤집히는 일이 줄었다고 생각한다.

나아가 문제도 있었다. 신입 2명은 첫 3개월 동안 질문할 사람을 찾기 어려웠다고 답했다. 메신저 응답이 늦을 때 일이 멈췄다. 신입에게는 출근일을 더 늘리는 것이 맞다고 생각한다.

결론적으로 재택근무는 통근과 기록 측면에서 효과가 있었고, 신입 적응에는 약점이 있었다. 나는 혼합 방식이 답이라고 생각한다. 이번 경험을 통해 소통의 중요성을 깨달았다.
```

발화: "report.md 다듬어줘"

통과 기준:
- 종결이 `~다`체 그대로다
- 다듬은 뒤 `slop_scan.py --prose`에서 PROSE_THINK, PROSE_CONNECTOR WARN이 사라진다
- 숫자(2025년 3월, 8명, 5명, 2시간, 주 5회, 주 2회, 30%, 90%, 2명, 3개월)가 그대로 남는다
- 원문에 없는 사실, 수치, 출처, 바뀐 행동을 더하지 않는다
- 스캔 결과(PASS/FAIL)를 보고한다
