# jasoseo 플러그인 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** stop-slop-ko 마켓플레이스에 자소서 인터뷰 플러그인 `jasoseo`를 추가한다. 인터뷰로 지원자 경험을 카드로 모으고, 카드의 사실과 본인 말투로만 초안을 쓰고, 글자 수를 스크립트로 잰다.

**Architecture:** 스킬 하나(`SKILL.md`)가 흐름을 안내하고, 세부 규칙은 `references/` 네 파일로 나눈다. 코드는 글자 수 계산기 `count.py` 하나뿐이다(표준 라이브러리). stop-slop-ko 훅은 자소서 요청에서 빠지도록 고친다.

**Tech Stack:** Claude Code 플러그인(마크다운 스킬), Python 3.8+ 표준 라이브러리, unittest

**Spec:** `docs/superpowers/specs/2026-10-10-jasoseo-design.md`

## Global Constraints

- 플러그인 이름 `jasoseo`, 플러그인 ID `jasoseo@stop-slop-ko`
- stop-slop-ko에 의존하지 않는다. jasoseo 안의 파일만으로 동작한다
- 경험 은행: 작업 폴더의 `jasoseo/stories.md`. 초안: `jasoseo/<회사>-<직무>/<문항번호>.md`
- 초안 길이 목표: 글자 수 제한의 90~100%
- 글자 수 기본 기준: 공백 포함(줄바꿈 1자)
- 카드에 없는 경험, 숫자, 역할은 만들지 않고 `[확인 필요: ...]`로 남긴다
- AI 탐지기 회피 기능은 넣지 않는다
- 스크립트는 Python 표준 라이브러리만, Python 3.8 이상
- 스킬 안 스크립트 경로는 `${CLAUDE_SKILL_DIR}/scripts/...` (stop-slop-ko SKILL.md와 같은 방식)
- 버전: marketplace 1.1.0, jasoseo 1.1.0, stop-slop-ko 1.1.0, stakeholder-brief 1.0.2 유지
- 사람이 읽는 한국어 문서(README, references)는 stop-slop-ko 스캐너 PASS
- 개인 저장소 규칙: 커밋·PR 전 `codex-review` 교차 리뷰

## Review Focus

1. Windows 메모장에서 ANSI(CP949)로 저장한 초안 파일: UTF-8로 못 읽어도 CP949로 읽어 세야 한다 → Task 1 `test_cp949_file`
2. 초안 파일의 제목 줄과 `<!-- -->` 메모: 본문 글자 수에 넣지 않아야 한다 → Task 1 `test_heading_and_comment_removed`
3. 이모지 등 EUC-KR에 없는 문자: 바이트 수를 세되 옛 채용 사이트에서 깨질 수 있다고 경고해야 한다 → Task 1 `test_emoji_not_in_euckr`
4. 두 플러그인을 다 설치한 사용자가 "자소서 초안 써줘": stop-slop-ko 훅이 개조식 문서 작성으로 끼어들면 안 된다 → Task 3 selftest
5. 사용자가 "그냥 지어내 줘"로 압박: 사실을 만들지 않고 `[확인 필요]`로 남겨야 한다 → Task 5 시나리오 1

import subprocess
import sys
import tempfile
import unittest
from pathlib import Path

ROOT = Path(__file__).resolve().parent.parent

class CountTest(unittest.TestCase):
    def test_hangul_and_spaces(self):
        c = C.count("안녕 하세요")
        self.assertEqual(c["space"], 6)
        self.assertEqual(c["nospace"], 5)
        self.assertEqual(c["utf8"], 16)
        self.assertEqual(c["euckr"], 11)

    def test_newlines(self):
        c = C.count("가나\n다라")
        self.assertEqual(c["space"], 5)
        self.assertEqual(c["space_no_newline"], 4)
        self.assertEqual(c["nospace"], 4)

    def test_crlf_normalized(self):
        self.assertEqual(C.count("가\r\n나")["space"], 3)

    def test_heading_and_comment_removed(self):
        text = "# A사 2번\n<!-- 제한: 700 -->\n\n본문입니다.\n"
        self.assertEqual(C.count(text)["space"], 6)

    def test_multiline_comment_removed(self):
        text = "<!--\n메모\n-->\n본문"
        self.assertEqual(C.count(text)["space"], 2)

    def test_emoji_not_in_euckr(self):
        c = C.count("좋아👍")
        self.assertEqual(c["space"], 3)
        self.assertEqual(c["non_euckr"], ["👍"])
        self.assertEqual(c["euckr"], 6)

    def test_gaps(self):
        self.assertEqual(C.count("팀원 [확인 필요: 인원 수]명")["gaps"], 1)

    def test_empty(self):
        self.assertEqual(C.count("# 제목만\n")["space"], 0)

    def test_judge(self):
        self.assertEqual(C.judge(630, 700), "ok")
        self.assertEqual(C.judge(629, 700), "under")
        self.assertEqual(C.judge(700, 700), "ok")
        self.assertEqual(C.judge(701, 700), "over")

```python
# -*- coding: utf-8 -*-
"""jasoseo 글자 수 계산기.

자소서 초안 본문의 글자 수를 채용 사이트에서 쓰는 여러 기준으로 센다.
초안 파일의 `#` 제목 줄과 `<!-- -->` 메모는 본문에서 뺀다.

usage: python count.py [FILE ...] [--limit N] [--basis space|nospace]
exit : 0 = 제한 안(또는 제한 없음), 1 = 제한 초과, 2 = 입력 오류
"""
import argparse
import re
import sys
from pathlib import Path

COMMENT = re.compile(r"<!--.*?-->[ \t]*\n?", re.S)
HEADING = re.compile(r"^#{1,6}\s.*(?:\n|$)", re.M)
GAP = re.compile(r"\[확인 필요[^\]]*\]")
WS = re.compile(r"\s")
LOW_PCT = 90
BASIS_LABEL = {"space": "공백 포함", "nospace": "공백 제외"}


def body(text):
    text = text.replace("\r\n", "\n").replace("\r", "\n")
    text = COMMENT.sub("", text)
    text = HEADING.sub("", text)
    return text.strip()


def euckr_bytes(text):
    total, bad = 0, []
    for ch in text:
        try:
            total += len(ch.encode("cp949"))
        except UnicodeEncodeError:
            total += 2
            bad.append(ch)
    return total, bad


def count(text):
    b = body(text)
    euckr, bad = euckr_bytes(b)
    return {
        "space": len(b),
        "space_no_newline": len(b.replace("\n", "")),
        "nospace": len(WS.sub("", b)),
        "utf8": len(b.encode("utf-8")),
        "euckr": euckr,
        "non_euckr": sorted(set(bad)),
        "gaps": len(GAP.findall(b)),
    }


def judge(n, limit):
    if n > limit:
        return "over"
    if n * 100 < limit * LOW_PCT:
        return "under"
    return "ok"


def report(name, c, limit=None, basis="space"):
    lines = [
        f"== {name}",
        f"공백 포함 {c['space']}자 (줄바꿈 제외 {c['space_no_newline']}자) | 공백 제외 {c['nospace']}자"
        f" | UTF-8 {c['utf8']}B | EUC-KR {c['euckr']}B",
    ]
    if c["non_euckr"]:
        lines.append(f"! EUC-KR에 없는 문자 {''.join(c['non_euckr'])}: 2바이트로 셈, 옛 채용 사이트에서는 깨질 수 있음")
    if c["gaps"]:
        lines.append(f"! [확인 필요] {c['gaps']}곳 남음")
    status = None
    if limit:
        n = c[basis]
        status = judge(n, limit)
        rest = limit - n
        left = f"남음 {rest}자" if rest >= 0 else f"초과 {-rest}자"
        verdict = {"ok": "범위 안", "under": f"짧음(목표 {LOW_PCT}% 이상)", "over": "초과"}[status]
        lines.append(f"{BASIS_LABEL[basis]} 제한 {limit}자 중 {n}자 ({n * 100 // limit}%), {left}: {verdict}")
    lines.append("※ 사이트마다 세는 방식이 다릅니다(줄바꿈을 2자로 세는 곳도 있음). 제출 화면의 글자 수를 마지막으로 확인하세요.")
    return "\n".join(lines), status


def read(path):
    data = Path(path).read_bytes()
    try:
        return data.decode("utf-8-sig")
    except UnicodeDecodeError:
        return data.decode("cp949")


def main(argv=None):
    if hasattr(sys.stdout, "reconfigure"):
        sys.stdout.reconfigure(encoding="utf-8", errors="replace")
    ap = argparse.ArgumentParser(description="자소서 글자 수 계산")
    ap.add_argument("files", nargs="*")
    ap.add_argument("--limit", type=int)
    ap.add_argument("--basis", choices=["space", "nospace"], default="space")
    a = ap.parse_args(argv)
    if a.limit is not None and a.limit <= 0:
        print("--limit은 1 이상이어야 합니다", file=sys.stderr)
        return 2
    sources = []
    if a.files:
        for f in a.files:
            try:
                sources.append((f, read(f)))
            except (OSError, UnicodeDecodeError) as e:
                print(f"읽을 수 없음: {f} ({e})", file=sys.stderr)
                return 2
    else:
        sources.append(("stdin", sys.stdin.buffer.read().decode("utf-8-sig", errors="replace")))
    over = False
    for name, text in sources:
        out, status = report(name, count(text), a.limit, a.basis)
        print(out)
        over = over or status == "over"
    return 1 if over else 0


if __name__ == "__main__":
    sys.exit(main())
```

# 문항 유형별 질문 세트

인터뷰는 한 번에 질문 1~2개. 아래 질문을 다 묻지 않는다. 카드(`story-card.md`)의 빈 칸을 채우는 데 필요한 것만 고른다.

## 문항 유형 판별

| 유형 | 문항에 자주 나오는 말 | 실제로 묻는 것 |
|---|---|---|
| 지원동기 | 지원한 이유, 왜 당사, 관심을 갖게 된 계기 | 이 회사와 직무를 고른 개인적 계기와 근거 |
| 성장과정 | 성장 과정, 가치관, 영향을 준 경험 | 지금 일하는 태도를 만든 구체적 장면 |
| 직무역량 | 직무 관련 경험, 역량, 전문성, 문제 해결 | 직무에 필요한 능력을 실제로 써 본 경험과 과정 |
| 갈등·실패 | 갈등, 어려움, 실패, 극복 | 그 상황에서 내가 한 판단과 행동, 결과를 받아들인 방식 |
| 입사 후 포부 | 입사 후, 목표, 포부, 기여 | 직무 이해를 바탕으로 한 첫 1~3년 계획 |
| 기타 | 사회 이슈, 협업, 창의, 자유 주제 | 문항 문장이 묻는 것을 한 줄로 다시 쓴다 |

한 문항이 두 유형에 걸치면(지원동기와 입사 후 포부) 둘 다 적고, 글자 수를 어떤 비율로 나눌지 사용자에게 묻는다.

## 유형별 추가 질문

### 지원동기
- 이 회사나 직무를 처음 알게 된 때는 언제인가요?
- 이 회사 제품이나 서비스를 직접 써 본 적이 있나요? 그때 무엇이 눈에 들어왔나요?
- 다른 회사가 아니라 여기여야 하는 이유를 하나만 고르면요?
- 채용공고에서 가장 끌린 문장은 무엇인가요?

### 성장과정
- 지금 일하는 방식에 영향을 준 사람이나 장면 하나를 떠올려 보세요.
- 그 일 전후로 달라진 점을 행동으로 말하면요?
- 그 습관이 최근 경험에서 드러난 예가 있나요?

### 직무역량
- 문제를 처음 알아챈 계기는요?
- 원인을 찾으려고 무엇을 열어 보거나 시도했나요?
- 쓴 도구, 기술, 방법은요?
- 처음 시도가 안 됐다면 다음에 무엇을 했나요?
- 이 경험이 지원 직무의 어떤 업무와 닮았나요?

### 갈등·실패
- 의견이 갈린 지점은 정확히 무엇이었나요? 상대는 왜 그렇게 생각했나요?
- 내가 먼저 한 행동은요?
- 결과가 좋지 않았다면 그 뒤에 무엇을 바꿨나요?
- 지금 같은 상황이 오면 첫 행동은요?

### 입사 후 포부
- 입사 첫해에 맡을 거라 생각하는 일은요?
- 그 일에 바로 쓸 수 있는 내 경험이나 기술은요?
- 3년 뒤 어떤 일을 맡고 싶나요? 그러려면 무엇을 더 익혀야 하나요?

## 되묻기

답에 아래 말이 나오는데 뒤에 구체적 행동이나 숫자가 없으면 "예를 들면요?"로 한 번 더 묻는다.

- 열심히, 최선을, 노력, 성실히
- 소통, 협업, 리더십, 책임감, 주도적
- 많이, 크게, 성공적으로, 개선
- 배웠다, 성장했다, 깨달았다

## 경험이 없다고 할 때

# jasoseo

자소서를 대신 지어 쓰지 않는다. 질문으로 지원자 본인의 경험을 꺼내 경험 카드로 모으고, 카드에 있는 사실과 본인 말투로만 초안을 쓴다.

## 핵심 원칙

1. **사실은 카드에서만.** 카드에 없는 경험, 숫자, 역할은 만들지 않고 `[확인 필요: ...]`로 남긴다.
2. **본인 말투.** 사용자가 한 말을 원문 그대로 카드에 남기고 초안에서 살린다.
3. **글자 수는 스크립트로.** `count.py`로 잰다. 짐작으로 세지 않는다.

## 흐름

1. **입력**: 회사, 직무, 문항 원문, 글자 수 제한. 빠진 것만 묻는다. 채용공고를 주면 직무 키워드를 뽑아 둔다.
2. **문항 분석**: `references/question-bank.md`의 "문항 유형 판별" 표로 유형을 정해 보여 준다.
   ```
   유형: 직무역량
   묻는 것: 기술 문제를 스스로 찾아 풀어 본 경험과 과정
   제한: 공백 포함 700자
   ```
3. **경험 은행 조회**: `jasoseo/stories.md`를 읽고 맞는 카드 2~3개를 제시한다. 사용자가 고르거나 새 경험을 말한다. 파일이 없거나 맞는 카드가 없으면 4로 간다.
4. **인터뷰**: `references/question-bank.md`. 한 번에 질문 1~2개. 추상적인 답은 "되묻기" 규칙대로 다시 묻는다.
5. **카드 저장**: `references/story-card.md` 양식으로 `jasoseo/stories.md`에 추가하거나 고치고, 바뀐 카드를 보여 준다.
6. **초안**: `references/draft-rules.md`와 `references/jasoseo-style.md`를 따라 쓰고 `jasoseo/<회사>-<직무>/<문항번호>.md`에 저장한다. 글자 수를 재 제한의 90~100%에 맞춘다.
7. **점검 리포트**: `references/draft-rules.md`의 "점검 리포트" 양식. 사용자가 고친 본문을 주면 다시 낸다.
8. **사용 이력**: 쓴 카드의 사용 이력을 갱신한다.

카드가 이미 충분하면 3에서 6으로 간다. 사용자가 직접 쓴 자소서 첨삭을 부탁하면 7부터 한다. 이때 카드가 없으면 본문에 나온 사실을 카드로 옮길지 먼저 묻는다.

## 글자 수

```bash
python "${CLAUDE_SKILL_DIR}/scripts/count.py" <초안 파일> --limit <N>
```

- 기준은 공백 포함. 공백 제외 문항이면 `--basis nospace`.
- exit 0 제한 안, 1 초과, 2 입력 오류.
- 출력에 `[확인 필요] N곳`이 있으면 그 내용을 사용자에게 묻는다.
- Windows에서 `python`이 없으면 `py`, macOS와 Linux는 `python3`.
