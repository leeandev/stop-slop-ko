# stop-slop-ko 서술형 문체 설계

작성일: 2026-10-11
상태: 스펙 검토 완료(2026-10-11), 구현 계획 전

## 목적

stop-slop-ko는 지금 개조식 실무문서(회의록, 보고서, 메일, pptx/docx/xlsx) 기준이라 서술형 산문의 AI 티를 잡지 못한다. 리포트, 에세이, 자소서, 블로그·칼럼, 기고문 같은 서술형 글에도 같은 생성·정제·톤 맞춤 흐름을 쓰게 한다.

- 대상: 과제 리포트·에세이를 쓰는 학생, 블로그·칼럼을 쓰는 직장인, jasoseo 없이 자소서를 다듬는 사용자
- 성공 기준
  - 서술형 글을 새로 쓸 때 레지스터를 서술형으로 정하고, 교훈형 마무리·빈 강조어·"~라고 생각한다" 남발 없이 쓴다.
  - 정제 모드가 서술형 글의 종결어미를 바꾸지 않는다(`~다`는 `~다`, `~습니다`는 `~습니다`).
  - `slop_scan.py --prose`가 서술형 상투 패턴을 INFO·WARN으로 보고한다. `--prose` 없이 돌리면 지금과 결과가 같다.
  - 훅이 서술형 작성 요청에서 stop-slop-ko를 상기시키고, jasoseo가 설치·활성화된 경우 자소서 요청에는 끼어들지 않는다.

## 범위 밖

- AI 탐지기 회피. README와 스킬 어디에도 "검사기 통과" 같은 문구를 쓰지 않는다. 요청이 오면 목적이 아니라고 밝힌다.
- 대필. 사용자가 내용 없이 "리포트 대신 써 줘"라고 하면 문체 규칙은 적용하되, 사실·주장·출처를 지어내지 않는다.
- 영문 글, 소설·시 같은 창작물
- 인용·참고문헌 형식(APA 등) 점검

| 항목 | 결정 |

| 구조 | 모드를 새로 만들지 않는다. 생성·정제·톤 맞춤의 "레지스터 결정"에 서술형을 추가한다 |

| 문서 전체 WARN | 최소 횟수 + 밀도 둘 다 넘을 때(아래 스캐너 절) |

## 스킬 변경 (SKILL.md)

- 설명(frontmatter description)에 리포트, 에세이, 블로그 글, 칼럼, 자소서 다듬기 트리거를 추가한다.
- "언제 쓰나"에 서술형 글을 명시한다.
- 생성 모드 1단계 레지스터 결정에 서술형 분기를 추가한다. 기존 문서·이전 글이 있으면 그 문체가 기준이라는 원칙은 그대로다.
  - 서술형 판정: 위 글 종류이거나, 사용자가 문단 글을 요청했을 때
  - 서술형이면 `references/prose-patterns.md`를 읽고, 개조식 규칙(명사 종결, `~함/됨`) 대신 문단 서술로 쓴다.
- 정제 모드: 서술형 글이면 `--prose`로 스캔하고 prose-patterns의 조치를 따른다. 종결어미는 손대지 않는다.
- 톤 맞춤 모드: 기준 글이 서술형이면 시그니처 추출에 문단 길이, 문장 길이, 1인칭 사용, 연결어 빈도를 더 본다(`tone-extraction.md`에 항목 추가).
- 검증 절: 서술형 글은 `slop_scan.py --prose --info`로 확인한다.
- 자소서: jasoseo가 있으면 jasoseo를 쓰라고 안내하고, 없으면 이 스킬이 정제·생성 문체 패스만 맡는다(경험 인터뷰는 하지 않는다).

## prose-patterns.md

jasoseo-style.md의 자소서 패턴을 서술형 전반으로 넓히고, 글 종류별 상투구를 더한다. 각 패턴은 "신호 → 왜 AI 티인가 → 조치 → 전후 예시" 형식.

공통 패턴:

- 교훈형 마무리: "~을 깨달았다", "~의 중요성을 알게 되었다"로 문단·글 끝맺기
- "단순한 ~이 아닌 ~이다" 대비 틀
- 명언·사전 정의로 시작하기
- 빈 강조어: "정말", "매우", "진정한", "핵심적인", "무엇보다"
- "~라고 생각한다" 반복
- 연결어로 시작하는 문단 연속("또한", "나아가", "결론적으로", "이처럼")
- 형용사 세 개 나열, 세 항목 리듬 반복
- 거창한 포부·일반론 결말("앞으로 ~하는 사람이 되겠다", "~은 우리 모두의 과제다")

글 종류별 상투구:

- 리포트·과제: "본 보고서에서는 ~에 대해 알아보고자 한다", "이상으로 ~을 살펴보았다", "시사하는 바가 크다"
- 블로그: "오늘은 ~에 대해 알아보겠습니다", "~하는 꿀팁", "도움이 되셨길 바랍니다", "그럼 시작해 볼까요?"
- 칼럼·기고문: "~하는 시대다", "그 어느 때보다", "~해야 할 때다"

## slop_scan.py --prose

`--prose`를 주면 기존 규칙에 서술형 규칙을 더해 검사한다. 기존 규칙과 exit 코드(0 PASS, 1 WARN, 2 입력 오류)는 그대로다.

위치별 INFO(줄 단위로 보고, 판단은 사람이):

| 코드 | 신호 |
|---|---|
| PROSE_LESSON | 교훈형 마무리 |
| PROSE_NOTJUST | "단순한/단순히 ~이 아닌/아니라" |
| PROSE_QUOTE_OPEN | 글 첫 문단이 따옴표 인용이나 "사전적 의미"로 시작 |
| PROSE_EMPTY_EMPH | 빈 강조어 |
| PROSE_CLICHE_REPORT | 리포트 상투구 |
| PROSE_CLICHE_BLOG | 블로그 상투구 |

문서 전체 WARN(글 전체를 세어 기준을 넘으면 `(문서 전체)` 위치로 한 건 보고):

| 코드 | 기준 |
|---|---|
| PROSE_THINK | "~라고 생각한다/생각합니다" 3회 이상, 그리고 공백 포함 1,000자당 1회 이상 |
| PROSE_CONNECTOR | 연결어로 시작하는 문단 3개 이상, 그리고 전체 문단의 25% 이상 |

- 고정 횟수만 쓰면 긴 글에서 정상 빈도가 오탐된다. 최소 횟수(짧은 글 보호)와 밀도(긴 글 보호)를 둘 다 넘을 때만 WARN이다. 예: 800자 글은 3회부터, 6,000자 글은 6회부터.
- 연결어는 글 길이보다 문단 수에 비례하므로 문단 비율로 본다.
- WARN 메시지에 실제 값을 함께 낸다(예: "4회 / 1,000자당 1.3회", "문단 20개 중 6개").
- 문단 단위 판정은 기존 추출기(md, html, docx, pptx, xlsx)의 문단 목록을 쓰되, md는 빈 줄 없이 이어진 줄을 한 문단으로 묶고, 셀 안의 빈 줄은 문단 구분으로 본다. txt는 줄바꿈 하나로 문단을 나누는 글이 많아 묶지 않는다. 제목 줄과 목록 항목은 따로 세고, 표 셀과 md 머리말(front matter)은 세지 않는다. 첫 문단 판정도 머리말 다음부터 본다(최종 리뷰 반영, 2026-10-11). 글자 수는 한글이 있는 문단 텍스트의 합이다.
- 기준값(3회, 1,000자, 25%)은 상수로 두고 짧은 글·긴 글 양쪽 경계를 테스트한다.

## 훅 (stop-slop-doc-reminder.py)

- 문서 키워드에 서술형 키워드를 추가한다: 리포트, 레포트, 에세이, 과제물·수업 과제(학교 맥락이 붙은 "과제"만), 소논문, 독후감, 감상문, 블로그 글, 칼럼, 기고문.
- 버그·에러·테스트·커버리지 같은 개발 리포트와 주간·월간·매출·실적 같은 업무 리포트는 사이에 한 단어가 끼어도("버그 분석 리포트") 서술형으로 보지 않는다. DB·테이블·CSV·엑셀 맥락의 "칼럼"도 서술형이 아니다. 회사 업무 "과제", 데이터 표의 "칼럼 이름/추가"도 마찬가지다(교차 리뷰에서 발견, 2026-10-11).
- 에세이, 블로그 글, 칼럼, "문단 글", "서술형"처럼 분명한 서술형 요청은 "보고서" 같은 개조식 키워드가 같이 와도 서술형이다("보고서를 참고해서 블로그 글 써줘"). 리포트·레포트만 개조식 키워드에 양보한다.
- 자소서 처리를 바꾼다. 지금은 자소서 요청이면 무조건 빠진다.
  - `~/.claude/plugins/installed_plugins.json`에 `jasoseo@stop-slop-ko`가 있고, `~/.claude/settings.json`의 `enabledPlugins`에서 false로 꺼지지 않았으면 빠진다(jasoseo 몫).
  - 그 밖에는 자소서도 서술형 문서로 보고 상기 메시지를 낸다.
  - 파일이 없거나 읽기·파싱에 실패하면 미설치로 본다.
- 서술형으로 판정한 요청의 상기 메시지에는 "서술형 레지스터, `--prose` 스캔"을 덧붙인다.
- `--selftest` 판정표에 서술형 사례와 자소서 두 상태(jasoseo 있음/없음)를 추가한다. 설치 여부는 테스트에서 경로를 주입해 바꾼다.

## 예외 상황

| 상황 | 동작 |
|---|---|
| 개조식 보고서인데 "보고서"라서 서술형으로 착각 | "보고서"는 기존대로 개조식. 서술형은 "리포트, 레포트, 과제" 같은 학술·과제 표현과 사용자가 문단 글을 원할 때만 |
| 블로그 글이 설치·사용법 안내 | `~습니다` 안내형으로 쓴다 |
| 기존 글 종결이 섞여 있음 | 정제는 손대지 않고 섞여 있다고 알린다. 통일은 톤 맞춤 모드에서 사용자가 기준을 정할 때만 |
| "검사기에 안 걸리게" 요청 | 목적이 아니라고 밝히고, 상투구를 걷어낸 본인 글이 결과적으로 가장 자연스럽다고 안내한다 |
