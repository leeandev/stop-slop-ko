# 한국어 슬롭 패턴 & 치환표

원본 stop-slop(영어 에세이용)을 한국어 실무문서에 맞게 정제한 규칙. **내용·사실·숫자·근거·기술용어는 보존**, 어조·부호·상투구만 손댄다. 문서의 기존 레지스터(개조식 vs 서술체)를 먼저 파악해 **존중**한다.

## A. 문장부호 신호
| 신호 | 문제 | 치환 |
|---|---|---|
| 산문 속 em-dash `—` 부연 | 한국어 산문에 드묾, 번역/AI 티 | 콜론 `:` · 괄호 · 문장 분리 |
| 공백 가운뎃점 ` · ` 를 리스트 구분자로 | 나열 남용 | 쉼표 `,` 또는 슬래시 `/` |
| 이중 공백 `  ·  ` | 기계 생성 티 | 단일 구분자 |
| 장식 `★` | AI 강조 티 | 삭제(강조는 볼드·색) |
| 수식기호 `÷ = ×` 산문 삽입 | 기계 티 | 말로("~로 나눔", "~은", "~에 …적용") |
| 곱슬 `" " ' '` vs 곧은 `" '` 혼용 | 일관성 결여 | **문서 기존 관례로 통일** |
| 조사 앞 공백(`"제시" 에`, `40,000 은`, `PoC 와`) | 기계 티 | 붙이기(`"제시"에`, `40,000은`, `PoC와`) |
| 범위 공백 `1K ~ 20K`, `API 에서` | 취향 | 붙이면 깔끔(`1K~20K`, `API에서`) |

`※`는 한국 문서의 정상 주석기호(과용만 주의). `▶ →`는 다이어그램·표의 흐름 표시로만 허용.

## B. 어휘·문장 신호 (번역투·상투구)
- **번역투:** "~에 대비 …상이" → "~와 다름" / "~을 통하여" 남발 → "~로·~으로" / "~에 있어(서)" → 생략·"~에서" / "~라 할 수 있다" → 단정 / 과도한 피동("~되어지다")
- **과한 명사화 상투구:** "일관성을 확보함", "…근거를 사전 합의함", "제고·도출·기함" → 풀어쓰거나 명사 종결로 단순화("…통일을 위한 …사전 확정")
- **완벽 3단 병렬**("A는 …으로, B는 …하며, C는 …함"): 기계 리듬 → 필요 시 문장 분할·변주. **단, 내용상 3요소면 유지**(내용 ≠ 슬롭)
- **영어 stop-slop 규칙 중 한국어 적용 금지:** Wh-오프너 금지 / 3항목 리스트 금지 / "not X but Y" 금지 — 영어 에세이 신호이며 한국어 요구사항·스펙 열거는 정상 내용

## C. 레지스터별 종결 (개조식 문서)
**🔒 정제 모드는 종결어미를 바꾸지 않는다.** 아래는 "관찰"용이지 "변환"용이 아니다. 종결(`함/됨/한다/합니다`)은 저자 레지스터이며 슬롭이 아니다. 종결을 바꾸는 건 **톤 맞춤 모드**에서 기준 시그니처에 맞출 때뿐.
- 소제목·라벨: 흔히 **명사 종결(体言止め)** — 구성/구축/정의/적용/정보
- 주석(※·*)·콜아웃 박스: 흔히 **~함/됨** — "필요함", "산정함", "구성됨"
- 각주 불릿(·): 흔히 명사 종결
- ⚠️ **본문 서술의 `~함`도 정상 개조식이다.** "본문이니 `~한다`로" 같은 변환 금지. 능동 "~한다"로 억지 변환은 영어 stop-slop 오적용(실제로 이 스킬 테스트에서 subagent가 `정의함→정의한다`로 바꾸는 오류가 나왔다 → 이 규칙으로 차단).
- **서술체 문서**(고객 메일·설명문)면 저자의 "~합니다/~한다"를 그대로 두고, A·B의 부호·번역투만 정리.

### 종결 관련 red flags — 이 생각이 들면 멈춰라
- "이건 본문 문장이라 `~함`이 어색하다" → 종결 불변. 부호·번역투만.
- "능동태가 더 낫다 / 더 자연스럽다" → 정제 모드 아님. 톤 맞춤 모드에서 기준 샘플로만.
- "명사 종결이 밋밋하다" → 밋밋함은 슬롭이 아니다.
