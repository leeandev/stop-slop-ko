# 문체 시그니처 추출 & 맞춤 (tone-match)

"내 글을 남의 톤에 맞춘다." 동료가 쓴 다른 장·기존 승인 문서와 어투를 통일할 때.

## 1. 기준 샘플 확보
맞출 대상(같은 데크의 다른 장, 기존 승인 문서)을 **편집 안 된 원본**에서 확보. 여러 장이면 대표 3~5개.

## 2. 시그니처 추출 (6축)
| 축 | 관찰 포인트 |
|---|---|
| 종결어미 | 소제목=명사종결? `~함`? `~한다`? / 주석=? / 본문=? — **요소별로 다를 수 있으니 뭉뚱그리지 말 것** |
| 문장부호 | em-dash·middot·괄호·콜론·`>` 사용 습관, 따옴표 곧은/곱슬, 괄호 안 공백 습관 |
| 목록기호 | 쉼표 / 슬래시 / `>` / 번호 / 줄바꿈 중 무엇을 쓰나 |
| 조사 밀도 | 조사 최소 "명사 나열"형 vs 조사 갖춘 완결문형 |
| 용어·외래어 표기 | 영어 그대로 vs 음차, 붙임 표기, 괄호 병기 습관 |
| 길이·리듬 | 한 줄 요약형 vs 여러 절, 평균 길이 |

서술형 기준 글(리포트, 에세이, 블로그, 칼럼)이면 아래 축을 더 본다.

| 축 | 관찰 포인트 |
|---|---|
| 문단 길이 | 문단당 문장 수, 한 문장 문단을 쓰나 |
| 문장 길이 | 평균 길이, 짧은 문장과 긴 문장을 섞는 습관 |
| 1인칭 | 나 / 저 / 필자 / 생략 중 무엇을 쓰나 |
| 연결어 빈도 | 문단 첫머리 연결어("또한", "그런데")를 얼마나 쓰나 |

## 3. 요소별 매핑
같은 종류끼리 맞춘다: 내 소제목 → 기준 소제목 톤, 내 주석 → 기준 주석 톤. 한 문서 안에서도 소제목(명사종결)과 주석(`~함`)의 종결이 다를 수 있다.

## 4. 재작성
시그니처대로 재작성 + `ko-slop-patterns.md` 정제 규칙 동시 적용. **내용·숫자·근거 보존.**

## 5. 검증
기준 샘플과 나란히 놓고 종결·부호·목록기호 일치 확인. 원본 백업 대비 변경 범위 격리.

## 실사례 (이 방법이 나온 곳)
설계 데크에서 **1~13장 저자 시그니처** = 소제목 명사종결("…검색 화면 구성/구축"), 주석 `~함`("변경 필요함.", "상세설계함"), em-dash·★ 없음, 목록은 쉼표·`>`·줄바꿈, 곧은 따옴표.
→ 나중에 붙인 **14~17장**의 "…일관성을 확보함(3단 병렬 소제목) + em-dash + ★ + 공백 middot"을 이 시그니처로 통일: 소제목 명사종결, 주석 `~함`, 부호 정리.
→ **핵심 교훈:** 능동 "~한다"로 바꾸지 않았다. 그건 저자 톤이 아니고 영어 stop-slop의 오적용이다. 톤 맞춤은 "직설·능동으로 개선"이 아니라 "기준 저자처럼" 쓰는 것.
