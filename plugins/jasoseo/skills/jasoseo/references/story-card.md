# 경험 카드와 경험 은행

## 파일 위치

- 경험 은행: 현재 작업 폴더의 `jasoseo/stories.md`. 없으면 만든다.
- 초안: `jasoseo/<회사>-<직무>/<문항번호>.md` (예: `jasoseo/A사-백엔드/q2.md`)
- 시작할 때 `jasoseo/stories.md`가 있으면 먼저 읽는다.

처음 만들 때 맨 위에 넣는 내용:

```markdown
# 경험 은행

<!-- jasoseo 플러그인이 관리하는 파일. 직접 고쳐도 된다. 주민등록번호, 연락처, 주소는 적지 않는다. -->
```

## 카드 양식

```markdown
## [S03] 졸업작품 서버 장애 대응
- 시기·상황: 2025.03~06, 4인 팀 졸업작품, 시연 2주 전 서버 다운
- 내 역할: 백엔드 담당
- 한 일: 로그 분석 → DB 커넥션 누수 발견 → 풀 설정 수정
- 결과(숫자): 응답 3초 → 0.4초, 시연 정상 진행
- 어려웠던 점·선택: 기능 추가 vs 안정화 중 안정화를 주장
- 배운 점(본인 말): "고치는 것보다 원인 찾는 게 오래 걸린다는 걸 알았다"
- 쓸 만한 문항: 직무역량, 갈등·실패
- 원문 인용: "새벽 3시에 로그 보다가 커넥션이 안 닫히는 걸 봤어요"
- 사용 이력: A사 백엔드 2번 문항 (2026-10)
```

## 칸 규칙

| 칸 | 규칙 |
|---|---|
| ID | `S01`부터 순번. 지운 번호는 다시 쓰지 않는다 |
| 제목 | 경험을 한 줄로. 꾸밈말 없이 |
| 시기·상황 | 연월, 규모(인원, 기간), 배경 |
| 내 역할 | 내가 맡은 것. 팀 전체가 한 일과 구분한다 |
| 한 일 | 내가 직접 한 행동을 순서대로 |
| 결과(숫자) | 숫자나 눈에 보이는 변화. 없으면 `(숫자 없음)` |
| 어려웠던 점·선택 | 갈림길과 내가 고른 쪽 |
| 배운 점(본인 말) | 사용자가 한 말을 큰따옴표로 그대로 |
| 쓸 만한 문항 | 문항 유형 이름 |
| 원문 인용 | 사용자 발화를 고치지 않고 1~3개. 초안 말투의 재료 |
| 사용 이력 | 이 카드를 쓴 회사, 문항, 연월 |

모르는 칸은 지우지 않고 `(미확인)`으로 둔다. 초안에 그 내용이 필요하면 `[확인 필요: ...]`로 남긴다.

## 관리 규칙

- 같은 경험이면 새 카드를 만들지 않고 기존 카드를 고친다. 제목과 시기가 비슷한 카드가 있으면 같은 경험인지 사용자에게 묻는다.
- 사용자가 말한 내용과 다르게 요약하지 않는다. 카드를 저장하거나 고치면 바뀐 칸을 사용자에게 보여 준다.
- 동료 실명이나 회사 내부 정보가 들어가면 일반 명칭(팀원 A, 고객사)으로 바꾸자고 제안한다.
- 초안을 쓴 뒤 사용 이력을 갱신한다. 같은 회사의 다른 문항에 같은 카드를 또 쓰려 하면 겹친다고 알려 준다.
