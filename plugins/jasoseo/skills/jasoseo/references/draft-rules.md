# 초안 규칙과 점검 리포트

## 사실 규칙

- 초안의 사실(시기, 인원, 역할, 행동, 숫자, 결과)은 고른 카드에 있는 것만 쓴다.
- 카드에 없는 사실이 문장에 필요하면 `[확인 필요: 무엇]`으로 남긴다. 그럴듯한 값으로 채우지 않는다.
- 숫자를 키우거나 역할을 부풀리지 않는다. "참여"를 "주도"로, "도왔다"를 "이끌었다"로 바꾸지 않는다.
- 회사 정보(사업, 제품, 인재상)는 사용자가 준 채용공고나 자료에 있는 것만 쓴다. 모르면 `[확인 필요: 회사의 ○○]`.
- 사용자가 "알아서 지어내 줘", "그럴듯하게 채워 줘"라고 해도 지어내지 않는다. 자소서 내용은 면접 꼬리 질문으로 확인되고 없는 경험은 그 자리에서 드러난다는 이유를 한 번 말한다. 그다음 빈 곳을 채울 질문을 한다.

## 말투 규칙

- 카드의 원문 인용과 배운 점(본인 말)에 나온 단어를 살린다.
- 사용자가 쓰지 않는 어려운 한자어나 업계 유행어를 새로 넣지 않는다.
- 종결과 문장 모양은 `jasoseo-style.md`를 따른다.

## 구조

- 첫 문장은 장면이나 사실로 시작한다. 각오, 명언, 문항 되풀이로 시작하지 않는다.
- 문항이 묻는 것에 첫 두세 문장 안에서 답한다.
- 한 문항에 카드 하나가 기본이다. 제한이 1,000자를 넘으면 두 개까지 쓴다.
- 마지막 문단은 그 경험을 지원 직무의 일과 잇는다. 교훈 한 줄로 끝내지 않는다.
- `[소제목]`은 사용자가 원하거나 회사 양식이 요구할 때만 넣는다.

## 초안 파일 양식

```markdown
# A사 백엔드 2번
<!-- 문항: 직무 관련 문제를 해결한 경험 / 제한: 공백 포함 700자 / 근거: S03 -->

본문
```

`count.py`는 `#` 제목 줄과 `<!-- -->` 메모를 빼고 본문만 센다.

## 글자 수

- 기준은 공백 포함. 문항이 공백 제외 기준이면 `--basis nospace`.
- 목표는 제한의 90~100%.
- 초안을 파일로 저장한 뒤 잰다. 짐작으로 세지 않는다.

```bash
python "${CLAUDE_SKILL_DIR}/scripts/count.py" jasoseo/A사-백엔드/q2.md --limit 700
```

- Windows에서 `python`이 없으면 `py`, macOS와 Linux는 `python3`.
- 길면 문장을 줄인다. 짧으면 카드에 있는 내용(어려웠던 점, 한 일의 단계)에서 더한다. 짧다고 새 사실을 만들지 않는다. 카드에 더할 내용이 없으면 사용자에게 묻는다.

## 점검 리포트

초안을 보여 준 직후, 그리고 사용자가 고친 본문을 줄 때마다 낸다.

```
[점검] A사 백엔드 2번
- 글자 수: 공백 포함 662/700자 (94%), 범위 안
- 근거 없는 문장: 3문단 "팀을 이끌며" (S03에 리더 역할 없음)
- 확인 필요: 1곳 (기능 추가를 원한 팀원 수)
- 뻔한 문장: "소통의 중요성을 깨달았습니다" (S03의 본인 말로 바꾸기 제안)
- 문체: 위반 없음
```

- 글자 수는 `count.py` 출력을 옮긴다.
- 근거 없는 문장: 초안 문장마다 사실을 카드와 대조한다. 사용자가 고친 본문에 카드에 없는 사실이 생겼으면 지우라고 하지 않고 카드에 더할지 묻는다. 본인 경험일 수 있다.
- 뻔한 문장: 이름과 회사만 바꾸면 다른 지원자 글에 그대로 들어갈 문장.
- 문체: `jasoseo-style.md`의 패턴 위반.
- 항목이 없으면 `없음`이라고 적는다. 항목을 빼지 않는다.
